# 导入流程（v2 流式版）
#
# 本文说明 EntHub 的 Excel 导入流程设计、关键行为与注意事项。对应代码 routes/import_flow.py。
#
# 设计目标
# - 低内存：无论文件多大（实测 21 万行 / 39MB），内存峰值稳定在 ~250MB，不把整个文件载入内存。
# - 不污染时间戳：只有数据真正变化时才刷新 updated_at。
# - 补全而非覆盖：电话 / 股东按归一化值增量合并，只追加新值、不覆盖主号。
#
# 三段流程
#
# 1. 上传 /import/upload
#    - 上传的 xlsx 落盘到临时目录，再用 openpyxl read_only 只读「表头 + 前 30 行」，全文件不入内存。
#    - 表头探测：读前 5 行找「公司名称 / 统一社会信用代码」等关键列，兼容导出文件前几行垃圾数据。
#    - 总行数取自 xlsx dimension 标签（瞬时）。
#    - 前 30 行样本写入 import_preview 表；路径 / 表头行号 / 字段映射 / 总数写入很小的 metadata JSON。
#
# 2. 预览 /import/preview/<batch_id>
#    读 metadata + import_preview 表，展示字段匹配、样本、总数。「跳过重复记录」复选框语义见下。
#
# 3. 确认导入 /import/confirm/<batch_id>
#    导入前自动备份。后台线程流式逐行处理，SSE 推送进度。
#
# 去重与更新规则（核心）
#   每行先清洗 + 归一化，再判定：
#     命中已有（按信用代码，否则按归一化名称）？
#       否 -> INSERT 新公司（created_at/updated_at = 进库时刻）
#       是 ->
#         ① 先合并电话 / 股东（仅追加库里没有的新值，不覆盖主号）——命中一律执行，
#            所以「重复但有新电话」也会被补全。
#         ② 计算工商字段签名(md5)与库内签名比对：
#            字段有变化 且 未勾「跳过重复」 -> UPDATE 变化字段，updated_at = 现在
#            仅补了电话/股东 -> updated_at = 现在（数据确实变了）
#            完全无变化 -> 跳过，不动 updated_at
#
# 字段签名(diff)口径
#   - 参与比对的列见 HASH_COLS（28 个工商字段）。不含 source_file，也不含
#     phone/other_phone/shareholders/other_email（后者由增量合并单独处理）。
#   - source_file(文件名) 不参与比对：换文件名重新导入不应触发更新。
#   - 空的传入字段不算变化：文件没带某字段（Excel 空、库里有值）不视为「改变」，
#     不会触发 UPDATE、不会刷新 updated_at。只有「传入值非空 且 与库里不同」才算真实变化。
#   - UPDATE 只写入非空的传入字段，所以即便覆盖也只会写入有值的新数据，不会清空库内已有值。
#   - 签名(md5) 仅用于快速跳过完全相同的记录；签名不同时会逐字段精确比对
#     （SELECT 该记录），确认是否真有非空字段变化，避免空字段造成误判。
#   - 已知边界：insured_count 等数值字段可能因旧库(pandas浮点 '1.0')与新文件(openpyxl整型 '1')
#     的字符串表示不同而被判为「变化」并刷新 updated_at；数值本身一致，属无害的格式自愈。
#
# 「跳过重复记录」复选框
#   这个选项控制：当某字段「库里和文件里都有值、但值不同」时，谁说了算。
#   勾选(默认)：保留库里的值，只补电话/股东。即「重复记录一律跳过字段更新」。
#   不勾选：用文件里的新值覆盖库里旧值（字段级 UPDATE，仅写非空且不同的字段）。
#   说明：由于空字段不算变化，「精简版」文件（字段比库里少）无论勾不勾选，
#   都不会清空库内已有数据——区别仅在于「双方都有值但不同」时是否覆盖。
#
# 注意事项
#   1. updated_at 语义：表示「这条数据最后一次被真正修改」。重新导入完全相同的文件不会动它。
#   2. 字段不对称：若导入文件比库里字段更少（如本文件经营范围/通信地址为空而库里有值），
#      签名判为「有变化」会走 UPDATE 并刷新 updated_at，但空值不覆盖，库内数据不丢。
#      若不希望这种时间戳刷新，导入这类精简版文件时勾选「跳过重复记录」即可。
#   3. 内存：峰值来自预加载索引（信用代码/名称->id、字段签名、电话集合、股东集合），约 120MB，与文件大小无关。
#   4. 性能：21 万行实测约 5 分钟。
#   5. 停止/取消：每 1000 行提交一次；停止时已提交部分保留（有导入前备份兜底）。
#   6. 临时文件：源 xlsx 副本和 metadata 存于系统临时目录，导入完成/取消时自动清理。
#
# 文件名与日期
#   file_date 仍从文件名提取（如 xxx_20260724.xlsx），但仅用于展示，不再参与去重判定。
#   旧版曾用它与 updated_at 比大小决定走 UPDATE 还是 merge，v2 已移除该耦合。
#   因此「文件名没日期」不会再导致全量 UPDATE。
#
# 后续大批量导入建议
#   - 源文件下载后带日期命名，便于追溯。
#   - 重复率高时优先勾选「跳过重复记录」，只补电话。
#   - 想确认净新增数量，可在导入前看预览页总数，或单独做差异扫描。
