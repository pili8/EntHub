# EntHub 模块可管理清单

> 最新更新：2026-09-14
> 依据：全部 12 个模块的代码依赖实测（模板 `url_for`、前端 `fetch`、外部调用方） + 实际代码核对

---

## 一、判定标准（三条红线 + 一条附加）

| 编号 | 红线 | 判定结果 |
|------|------|---------|
| R1 | 关掉后**任何页面都打不开**（模板里 `url_for` 硬引用，模板编译期报错） | 永久不可关 |
| R2 | 关掉后**失去不可替代的能力**（备份的恢复功能只此一处） | 永久不可关 |
| R3 | 关掉后别处**留下死按钮**，而该功能**你在用** | 不放开 |
| 附加 | 模块的**删除按钮**只对"后接入的模块"有意义——自带模块删了功能也没卸载 | 自带模块去掉删除入口 |

---

## 二、12 个模块逐条结论

| 模块 | 作用 | 关掉后的实际后果 | 判定 | 依据 |
|------|------|-----------------|------|------|
| **pages** | 搜索 / 浏览 / 电话可信度 / 关联发现 | **全站打不开**（所有页面的导航、底部按钮都硬指向它） | 🔴 永久不可关 | R1 |
| **companies** | 手动录入 / 企业详情 / 公司主数据 | **全站打不开**；公司数据是所有功能的地基 | 🔴 永久不可关 | R1 |
| **settings_flow** | 设置页 = 模块开关面板所在地 | 关掉后没有任何入口再打开其他模块（自锁死） | 🔴 永久不可关 | R1 |
| **tags** | 企业标签体系 | 详情页、浏览页的「打标签」按钮变成死按钮；**你常用标签** | 🔴 永久不可关 | R3 |
| **api_legacy** | 对外接口：统一搜索、号码统计、批量删除、批量打标签 | 浏览页的**批量删除/批量打标签失效**（唯一硬依赖）；`/api/search`、`/api/phone_stats` 消失 | 🔴 永久不可关 | R3 |
| **backup_flow** | 备份创建/下载/删除，**唯一的恢复入口** | 失去**唯一的数据回滚入口**：数据误删或损坏时，界面里回不到备份 | 🔴 永久不可关 | R2 |
| **mcp_flow** | MCP 服务的启停与状态面板 | 少一个面板；MCP 是独立进程，已在跑的不受影响 | 🟢 可管理 | — |
| **cleanup_flow** | 去重、清空无效值、压缩数据库 | 少一个整理工具入口，公司数据与检索不受影响 | 🟢 可管理 | — |
| **import_flow** | Excel 批量导入 | 导航「导入」与导入页消失；首页导入卡片自动隐藏；你很少用 | 🟢 可管理 | 决策 3 |
| **phone_wechat** | 号码对应微信号与备注接口 | 微信标记照常显示（数据由核心层读取），编辑按钮变灰不可点击 | 🟢 可管理 | 决策 2 + 3 |
| **phone_tags** | 号码标记（有效/无效/推销…）接口 | 标记按钮照常显示（数据由核心层服务端渲染），点击设置会失败 | 🟡 改造后可管理（暂不做） | 决策 2 + 3 |
| **quick_import** | 「一键标注」「从网页提取」的后端接口（**没有独立页面**，`/quick-import` 路由已只做 302 跳转到录入页） | 5 个入口一起失效：电话页「文本」标签、手机端底部 ⚡ 标注按钮、录入页「从网页提取」、Chrome 插件、macOS 菜单栏小工具。插件与菜单栏程序在服务端模块停用后会静默失败（客户端无法变灰） | 🟡 改造后可管理（暂不做） | 决策 3 |

## 三、最终清单

### A. 永久不可关闭 —— 8 个（无开关、无删除）

```
pages          核心页面（搜索 / 浏览 / 电话可信度 / 关联发现）
companies      手动录入 / 企业详情 / 公司主数据
settings_flow  设置页（模块开关面板宿主）
tags           标签管理
api_legacy     对外 API（含浏览页批量操作）
backup_flow    数据备份（含唯一的恢复入口）
quick_import   快速录入 / 一键标注（5 个入口都要改，暂不放开）
phone_tags     电话标记 API（改造成本低但用户选择保持核心）
```

### B. 可管理 —— 4 个（开关 + 删除入口）

```
mcp_flow       MCP 工具
cleanup_flow   数据整理
import_flow    Excel 批量导入（已放开，首页卡片加条件隐藏）
phone_wechat   电话微信关联 API（已放开，详情页 + 电话页微信按钮加变灰）
```

### C. 改造后可管理 —— 2 个（**暂不做**，留作将来）

```
phone_tags     电话标记    改造：详情页 + 电话页的标记按钮变灰
quick_import   一键标注    改造：5 个入口都要处理——
                                 ① 电话可信度页「文本」标签（完整的标注区块，主入口）
                                 ② 手机端底部 ⚡ 标注按钮（全站每个页面都有）
                                 ③ 录入页「从网页提取」
                                 ④ Chrome 插件（客户端无法变灰，只能提示"服务已停用"）
                                 ⑤ macOS 菜单栏小工具（同上）
```

## 五、明确不做

- ❌ 不为 `phone_tags` / `quick_import` 改模板（收益≈0）
- ❌ 不把 `tags` 放开（你常用它，且会在详情页/浏览页留死按钮）
- ❌ 不做热加载、不做插件市场、不拆 pip 包（沿用方案第九节既定结论）
- ❌ 不合并/拆分现有模块（各模块职责边界清晰，无重叠到需要合并的程度）

---

## 六、一句话总结

**12 个模块里，4 个适合给开关（MCP 工具、数据整理、Excel 导入、电话微信关联），其余 8 个要么关掉全站崩、要么丢失不可替代的能力、要么会弄坏你正在用的功能。**

"能关掉"这件事对你的价值，**不在关掉老功能，而在以后接新模块时不用改代码**——这个能力已经到位了（丢一个文件进 `routes/` 就自动注册 + 自动上菜单）。
