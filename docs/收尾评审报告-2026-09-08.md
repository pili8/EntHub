### 2.4 安全（已验证的高危链路）

```python
# app.py:19
app.secret_key = "enthub-dev-key-2024"          # 硬编码，公开可见
# app.py:283
app.run(host="0.0.0.0", port=APP_PORT, ...)     # 监听所有网卡

# config.py:54-70  load_config()
if not DB_PATH.exists(): return {}              # 静默降级
except sqlite3.OperationalError: return {}      # 静默降级

# config.py:73-87  save_config() —— 所有 save_* 都是 load→改→整包覆盖写
INSERT INTO settings ... ON CONFLICT(key) DO UPDATE SET value = excluded.value

# config.py:281-286
def verify_access_password(plain_password):
    password_hash = get_access_password()
    if not password_hash:
        return True        # ← fail-open：密码丢了就完全放行
```

**完整攻击/失效链**：

1. `load_config()` 在数据库不可用、settings 表不存在时**静默返回** **`{}`**
2. 此时任意一次 `save_*`（改 webhook、改配额、开关密码…）都会以 `{}` 为基底**整包覆盖**，抹掉 `access_password`、`api_providers`（含明文密钥）、`webhook_url`
3. 密码哈希一丢，`verify_access_password()` 返回 `True` → **认证失效且是静默的**
4. 即便密码还在，`secret_key` 硬编码意味着 session 签名可被伪造 → 登录页可绕过
5. 服务监听 `0.0.0.0` → 同一局域网任何人可访问

另外：`settings` 表只有 1 行（`key='config'`），整个配置是一个 JSON blob，**内含明文 API 密钥**（鲸海数据 `app_id` / `api_key`）与 Webhook URL。它随数据库一起进入坚果云同步目录和 7 份备份文件 —— **密钥已经被同步到云端、并躺在 3.6GB 的备份里**。

**补充实测发现**：API 认证支持 **URL 传密码**（`?token=密码` 或 `Authorization: Bearer`）。实测 `GET /api/companies` 返回：

```json
{"code":401,"message":"需要认证，请在 URL 加 ?token=密码 或 Authorization: Bearer 密码"}
```

URL 传凭证会泄漏到浏览器历史、服务器日志、代理日志和 Referer 头。**建议移除** **`?token=`** **方式，只保留 Header 或 Cookie。**

### 4.6 QA 的 WAL + 坚果云判断

> **这是唯一"什么都不做也会出事"的风险 —— 概率随时间单调上升。**

机理：SQLite 每次空闲/退出都会重建并删除 463MB 的 `-wal`/`-shm`，主库 mtime 随之变化 → 坚果云永远在追一个不停变化的大文件 → 冲突。8/14 一天三次冲突是直接证据。

⚠️ 冲突副本与主库**同目录、同前缀**，用户哪天在恢复下拉框里手滑选中，就是回滚甚至损坏。

缓解方案（按推荐度）：

1. **（S，推荐）库移出同步目录** → `~/Library/Application Support/EntHub/enthub.db`（bootstrap 的默认值本就如此，只是后来被手工改到了坚果云）。要多机同步就**同步备份文件**（`VACUUM INTO` 一致性快照），不同步活库
2. **（S）`journal_mode`** **改回** **`DELETE`**（`db.py:19` 一行）—— 单机单人场景，WAL 的收益远小于它在同步盘上的爆炸半径
3. **（S）先跑** **`PRAGMA integrity_check`** **确认主库完整**，再把 3 个冲突副本改名加 `.conflict` 后缀归档，**不要直接删**
4. **（M）若必须放坚果云**：加 `.nosync` 忽略规则，改由 EntHub 每天 `create_backup` 到专用导出目录
5. **（M）启动自检**：比对 DB 指纹（mtime/size），被外部改动则拒绝启动并强制先备份
