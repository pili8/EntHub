## 四、偏差与遗留（不影响主目标，但需知情）

**1. 移动端底部 Tab Bar 未动态化**（文档第六节明确要求三处同源）

`base.html:126-149` 仍是硬编码的「首页 / 搜索 / 标注 / 浏览 / 录入」。因这 5 项全部指向 core 模块路由，**不构成停用崩溃风险**，但新增模块不会出现在底部 Tab。

**2. core=True 的范围比文档扩大**

文档定位 4 个核心（pages / companies / import_flow / tags），实装 9 个：额外把 `phone_tags`、`phone_wechat`、`quick_import`、`api_legacy`、`settings_flow` 也设为 core。代码注释给出理由（被详情页 / Chrome 插件 / MCP 外部依赖）。**副作用：设置页目前只有 3 个模块可开关**（mcp_flow、backup_flow、cleanup_flow）。

**3. `init_module` 签名与文档不一致**

文档附录写 `def init_module(db)`，实装注册器是零参调用 `fn()`（`routes/__init__.py:78`），模块自行 `from db import DB_PATH`。照文档附录原样复制新模块会在 `init_module` 处抛 TypeError——已被 try/except 吞掉，只打印一行「init_module 执行失败」。**建议统一口径（改文档或改注册器传参）。**

**4. 开关存储位置微差**

文档说 settings 表 key=`module_config`；实装是 settings 表 `key='config'` 的 JSON 中 `module_config` 子键。功能等价，仅命名层级不同。

**5. `external` 字段无消费方**

`api_legacy` 标了 `external: True`，但设置页没有做「外部依赖」提示（文档给的是二选一，已走 core=True 这条路）。`depends_on` 机制注册器已实现，但当前无模块声明依赖，属「有轮子没上路」。

**6. 无 MODULE_META 的文件被静默跳过**

`routes/__init__.py:104-105` 直接 `continue`，无任何提示；文档说的「手动注册兜底」在注册器里并不存在（`app.py:261` 只额外注册了 `api_bp`）。当前 12 个文件都有 META 所以无影响，但将来新增路由忘写 META 会表现为「路由莫名 404」，排查无提示。

**7. 注册器非幂等**

`MODULES / ALL_MODULES / ENABLED_IDS` 是模块级全局且不清空，同一进程内多次调用 `register_blueprints()` 会累积重复菜单项（实测调用两次菜单项翻倍）。当前 `app.py` 只调一次，无实际影响；但若将来引入 `create_app()` 工厂或反复建 app 的测试，会踩坑。
